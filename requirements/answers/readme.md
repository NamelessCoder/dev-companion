# Answers — what a caller may conclude from one

The shape of an answer rather than its subject: what an empty one means, where
the reason for it lives, and what a query has to do to reach the thing it is
about.

See [the requirements readme](../readme.md) for how an entry is written and
when it is added.

- [`R-ANS-1`][R-ANS-1] — "Could not ask" never looks like "does not exist" · held
- [`R-ANS-2`][R-ANS-2] — The reason is in the data, not only in the text · held
- [`R-ANS-3`][R-ANS-3] — A component answer carries its source and its version · held
- [`R-ANS-4`][R-ANS-4] — A tool implements the query language it documents · held
- [`R-ANS-5`][R-ANS-5] — A console that answered "none" has answered · held
- [`R-ANS-6`][R-ANS-6] — A miss says what there would have been to find · held
- [`R-ANS-7`][R-ANS-7] — The discriminating terms of a query decide the answer · held
- [`R-ANS-8`][R-ANS-8] — The files answer where the console cannot · held
- [`R-ANS-8b`][R-ANS-8b] — A short term is not the prefix of a longer word · held
- [`R-ANS-9`][R-ANS-9] — The instructions say when to call the lookups that come first · held
- [`R-ANS-10`][R-ANS-10] — A component answers the query that names it · held
- [`R-ANS-11`][R-ANS-11] — A content element is answered by what it owns · held
- [`R-ANS-12`][R-ANS-12] — An answer that cannot read something says so · held
- [`R-ANS-13`][R-ANS-13] — The instructions fit what a client keeps · held
