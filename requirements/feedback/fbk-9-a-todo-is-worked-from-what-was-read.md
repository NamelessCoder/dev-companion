# R-FBK-9 — A todo is worked from what was read

**How a todo is worked is written down in one place, and every todo that is
handed over names it.**

What that page carries is what is read before the first change, that the step is
judged rather than executed, that a question the work turns on is settled from a
source rather than recalled, and that what has no source here is asked before
the change instead of decided quietly.

A todo prints as an instruction, and acting on one takes no reading at all. What
that skips is the half that decides whether the change is right: the todo's
paragraph is a claim written by a session that has ended, the code it describes
has moved since, and the question the step turns on is answerable from the
checkouts, the official documentation or this server's own tools — or is not
answerable here, which is a result and has three places to be recorded in.

The questions that stay open after all of that are the ones nothing in the
repository can close: which of two shapes is wanted, what an ambiguous paragraph
meant, whether a step is worth its cost. Those are asked, with the reading
already done and the options named, before the change rather than in the commit
that presents it — a choice made silently is not a question saved, it is a
question moved to where the answer costs a rewrite. Putting the todo back is one
of the answers offered, because the person asked may have none either, and a
todo that carries its open question into the next session is worth more than one
closed on a guess. It goes to the end of the queue when it does: `bin/cli next`
hands over the first queued item and has no notion of blocked, so one left in
place is handed to every session behind it.

Nothing can check that the reading happened. A todo worked from the checkouts is
shaped exactly like one worked from memory, and what this repository produces is
acted on unchecked: a statement in `knowledge/`, a skill in somebody else's
project, a requirement the next author is held to. So the demand is that the
procedure exists and travels with the todo rather than waiting to be looked up —
`bin/cli next` prints the pointer with every todo it hands over.

**From:** 2026-08-01. The order of the work was fully described — what is due,
in which order, what a finished todo leaves behind — and how one is actually
worked was described nowhere, which left the reading and the research to
whatever the session brought with it.

**Held by:** `TodoTest::everyTodoIsHandedWithThePageThatSaysHowOneIsWorked`,
which holds `Todo::PROCEDURE`, the page it names and the line `bin/cli next`
prints to each other; that a session read it is not guarded and cannot be.
