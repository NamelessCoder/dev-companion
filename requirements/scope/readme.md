# Scope — core conventions where they apply, and nowhere else

These are how [`R-AUD-1`](../audience/aud-1-three-audiences-not-one.md) and
[`R-AUD-2`](../audience/aud-2-the-audience-is-a-property-of-the-task.md) are met
in the tools that exist today. `outsideCore` is a boolean, and an audience is
not — the flag is the shape this took before the requirement above was written
down, and it will not survive it.

See [the requirements readme](../readme.md) for how an entry is written and
when it is added.

- [`R-SCO-1`][R-SCO-1] — Outside the core is recognised from structure, not wording · held
- [`R-SCO-2`][R-SCO-2] — outsideCore changes the payload, entry by entry · held
- [`R-SCO-3`][R-SCO-3] — A core-only intent needs evidence of core work · held
- [`R-SCO-4`][R-SCO-4] — The backend CSS conventions are named as the backend's · held
- [`R-SCO-5`][R-SCO-5] — Every tool applies the same outside-the-core check · held
- [`R-SCO-6`][R-SCO-6] — Every topic says what it is worth outside the core · held
- [`R-SCO-7`][R-SCO-7] — A client is offered only the half it can use · held
- [`R-SCO-8`][R-SCO-8] — What the scope excludes is not what the server answers · held
- [`R-SCO-9`][R-SCO-9] — Individual tools can be excluded after the profile · held
