# Write the route for a patch set on somebody else's change

`D-KNW-129` judged this 1a and settled where it lands: the mechanics go into
`knowledge/documents/core/contribution/gerrit-workflow.md` beside **Update an
Existing Patch**, and the two patch skills carry the routing. Establish first
what the case actually is — whether TYPO3 accepts a patch set uploaded onto
another author's open change, what the upload owes that author on the change
itself, and when a comment is the answer instead — from the contribution
workflow guide with `typo3_documentation_lookup` and from Gerrit's own
documentation; then verify in a scratch clone what `git commit --amend` writes
into the author and the committer of a commit somebody else made, and that the
`Change-Id` and the one-commit rule are unchanged by it. Write the section, then
the skills: `typo3-core-patch-checkout` gains the way in that starts from the
fetched patch set and carries local work onto it, its `references/checklist.md`
loses the clause ruling the case out, the ending where the work continues on the
review branch stops being an omission of **Put the checkout back**, and
`knowledge/task-intents.json` gains the word a session brings for it. The skill
half is shown and asked about before it is published, which
`documentation/contributing/writing-a-skill.rst` is the rules for.
