# Answer a permalink identifier from the manual inventories

Judged step 1b, taken on:
[`D-ANS-118`](../../decisions/answers/ans-118-a-permalink-identifier-is-resolved-from-the-inventories-the-manual-lookup-already-reads.md)
has the evidence and the boundary, including what was read against the live host
in that run, and the name it proposes. The tool validates an identifier,
resolves it to its page and reverses an old docs.typo3.org URL back to the
identifier that replaces it — all three out of the Sphinx inventory
`Manual\Documentation` already fetches and holds by `ETag`.

The first step is the one thing the judgement left open: which manuals it
answers for. This server searches four, `t3start`, `t3contribute` and
`t3sitepackage` resolve against manuals it does not, and the shortcode is not
derivable from the manual path — so establish the map from shortcode to manual,
and whether the system-extension manuals under `/c/` are in it.
`Documentation::pages()` reads only the `std:doc` role of the inventory, which
is where the widening starts.
