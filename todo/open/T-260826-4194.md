# Route a brief that triages an issue and then fixes it

Judged on 2026-08-27 as the ladder's step 3, routing, and written up in
[`D-SKL-081`](../../decisions/task-skills/skl-081-a-brief-spanning-triage-and-the-patch-it-leads-to-carries-both.md),
which holds the runs and the reasoning. The guides half was trimmed off the
feedback; the three levers below are what is left, and they are one gap seen
from three surfaces.

**First step, and the measured one.** `typo3_task_guide` with
`task="please find 1 old forge issue and fix it"` matches `triage` weakly and
answers `skills: []`, so the brief that names both halves reaches neither skill.
Making the needle strong is not the fix on its own: `D-SKL-078`'s own worked
example `fetch another old issue from Forge, create a branch, work it off`
already matches strongly, and its brief drops six patch items — the target
branch, the deprecation sweep, keeping the patch focused, the test coverage, the
targeted run and the commit message. The lever is the `changesNothing` fork in
`TaskIntents::owned()`, which has one slot where this brief needs two: name both
skills in order and keep the items the change owes. `D-SKL-039`'s third **Wrong
if** is the boundary — an author's brief may not lose its route.

**Second.** `typo3-core-issue-triage`'s description closes "Writing or reviewing
a patch is other work", and the session names that sentence as what pushed it
off a task ending in a patch. What it states is the crossing `D-SKL-022` made an
instruction in the body, standing in the description as a refusal. It is a
skill's contract in somebody else's project, so it is written under
[writing-a-skill](../../documentation/contributing/writing-a-skill.rst) and the
cap `SkillTest::everyDescriptionIsWrittenToALengthOfItsOwn` holds, which this
description sits well below. The reading is under the entry of 2026-08-27 in
`D-SKL-076`.

**Third.** `typo3_task_guide`'s description opens "Build a task checklist
enriched with matching hints and relevant core checks", against a core checkout
whose own `AGENTS.md` is read into every session and already gives one. That is
`D-AUD-014`'s statement on a second tool: the opening says what the caller's own
route cannot do — here the branches a `Releases:` trailer takes and whether the
change owes a changelog entry, both of which this session had to guess.

Each of the three is held by a test naming the words a brief arrives in and the
answer that has to follow, in the shape
`SkillTest::takingAnIssueOffTheTrackerReachesTheTriageSkill` already has.
