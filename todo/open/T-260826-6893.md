# Let the commit guide's description say it names the branches

`D-AUD-015` judged this step 4, wording. The tool already answers which branches
take a patch today and where a bug fix goes, and its description promises only
that the trailer is "held against" them — a check on what the caller supplies.
The sentence saying the tool supplies the set stands in the `releases` property
of `inputSchema()`, which a deferring client reads once the tool is already
chosen, so it sits behind the choice it had to cause.

The step is `CommitMessageGuide::description()`: turn the branch clause from a
check into a supply, so a caller holding no set reads that this call produces
one. The branches themselves stay out of it —
`decisions/answers/ans-073-what-can-take-a-patch-and-where-this-one-goes-are-two-readings.md`
is the boundary, and every one of those states is a date passing. Reread the
whole description afterwards rather than the clause: it is six sentences long,
and the judgement rests on where in it a caller stops reading.
