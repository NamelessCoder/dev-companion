# Lift the issues an issue's prose cites into a field

Step 1b, the shape, and `D-ANS-123` carries the reading: what the description
and the notes cite is in the payload and only inside a sentence, where
`relations: []` reads as nothing linked. Normal rather than low because the
citation is the reporter's claim about prior art, which is what a patch gets
framed against.

Build `mentioned` on the `issue` path of `typo3_forge_lookup`: in
`Forge::issueOf()`, read the description and the notes for
`forge.typo3.org/issues/NNN` and for bare `#NNNN` bounded to three to six
digits, drop the numbers `relations` already carries, and resolve the rest
through the `fields()` bulk read `related()` already makes — a number the
tracker does not answer for is dropped. Each entry carries `issue`, `subject`,
`tracker`, `status`, `url` and `where`, which is `description` or `note` and is
`description` where both name it. Declare it in `ForgeLookup::outputSchema()`
beside `relations`, print it in `read()` where `relations` is empty, and read
`reviews` from the description as well as from the journal in the same pass — 5
of the 100 newest open bugs carry a review URL there that no answer names today.
The enumeration rows are outside this, and `D-ANS-123` says why.
