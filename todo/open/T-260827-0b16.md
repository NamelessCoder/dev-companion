# I trusted forge_lookup reviews:[] as proof no patch was in flight and never opened Gerrit

Make `reviews` on a single issue the union of `changesForIssues()` and the
handles `Forge::reviews()` parses out of the text, deduplicated by change
number, and say in the field's description where the two halves come from —
[`D-ANS-125`](../../decisions/answers/ans-125-one-reviews-field-means-the-changes-the-review-server-holds.md),
which has what was read and what would show it wrong. The judgement is step 4
turning into a decision: `D-ANS-064` named the field for a prose handle and
`D-ANS-069` filled the same name from the review server for enumerated rows,
neither saw the other, and nothing says which call sourced which. It is `high`
rather than `low` because the two disagree the dangerous way round — the cheap
enumeration is authoritative about Gerrit and the deliberate single read is not
— and because the cost of the wrong reading is a duplicate patch a core reviewer
pays for. It touches `src/` and a declared schema, which is what kept it off the
spot rather than the size of the change.
