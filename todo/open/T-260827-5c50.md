# The guides listed by project_describe are read by rule_lookup, which no name says

Have a checklist item that summarizes a rule say which cases the summary does
not decide, beside the document id it already names. The reporting session read
the changelog item's one-sentence summary, judged from it that a bugfix touching
only an `@internal` class owed no entry, and never opened
`core/contribution/changelog` — where that edge is decided. It says the summary
"is good enough often enough that the document never gets opened", which is the
same failure the `when` line and the `tool` field were built against and the one
neither of them reaches: a caller who has an answer does not go looking for a
better one. What to settle first is where the sentence lives — in the checklist
item, which is written per intent in `knowledge/task-intents.json`, or in the
document, which would make it the page's own statement about its edges and
reachable from every surface that names the page. It is `normal` because one
session reported it and it changes what every brief weighs, so it is not a
wording fix at one site. The naming half of this feedback is answered and gone:
the reading is under 2026-08-27 in
[`D-GUI-012`](../../decisions/guides/gui-012-the-brief-names-the-guide-the-recognized-work-belongs-to.md).
