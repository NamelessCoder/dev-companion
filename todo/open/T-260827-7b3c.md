# A corpus rewrap collides with the cards other branches rewrite

`bin/cli prose:format` named with no path rewraps the whole corpus, and a
session working a claimed todo runs it that way, so its commit carries every
file a rename left ragged — including the cards the other claimed sessions are
rewriting at the same moment. That collided twice on 2026-08-27, on
`todo/T-260824-bd21` and on `todo/T-260824-ea52`, both times on cards another
branch had rewritten wholesale or deleted, and both times `bin/cli todo:home`
stopped on the conflict with the rebase aborted behind it. The resolution was
the same on both: keep what `main` says about a card the branch only rewrapped,
after which one of the two rewrap commits reduced to empty and dropped out.
Settle whether a session holding one todo may rewrap files no part of its own
work touched — the alternatives are a `prose:format` that rewraps only what the
branch changed, a corpus sweep that is `main`'s alone and never a claimed
branch's, and leaving it as a conflict `todo:home` teaches whoever meets it.
Read what `bin/cli todo:home` should do with the class before choosing, since a
delete-versus-rewrap conflict has one right answer every time and the command
resolves none of it today.
