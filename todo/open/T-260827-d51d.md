# Archiving a feedback breaks the links another branch just wrote to it

`bin/cli feedback:archive` moves a report into `feedback/archive/` and repoints
what names it, and a decision written on another branch in the same window names
it too — that branch merges first, and the archiving branch then fails
`LinksTest` on a link its own session never saw. It happened three times on
2026-08-27, on `todo/T-260825-6e96`, `todo/T-260826-1572` and
`todo/T-260826-4194`, each time on a decision a judging run had merged after the
archiving branch was cut, and each time `bin/cli links:check` named the file and
the line. The repair is mechanical every time: the path gains `archive/` and
nothing else, which is why it is worth doing once rather than by hand in each
session that meets it. Settle where that belongs — `feedback:archive` cannot see
a link that does not exist yet, so the candidates are `todo:home` repairing the
class after it rebases, a check that reads the archive before it reports a dead
link, and `links:check` naming the repair it already knows. Read what
`D-DOC-063` settled about `prose:format` first: it is the same shape, a branch
sweeping files the merge target moved underneath it, and the reasoning there
rejected auto-resolution in `todo:home` for a case with more than one right
answer — this one has exactly one.
