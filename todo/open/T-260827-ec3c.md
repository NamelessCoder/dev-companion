# A changelog file lands in the newest directory because nothing names the oldest

The maintainer reports on 2026-08-27 that sessions keep writing a backport's
changelog entry into the directory of the release under development, and three
surfaces were measured that day against `.checkouts/main`: `typo3_rule_lookup`
on `write a changelog entry for a bugfix` returns *Which Change Owes a Changelog
File*, *What a Changelog File Carries* and *What a Changelog File Is Called* and
not *Where a Changelog File Goes*, while `add a changelog file` reaches the
document not at all; `typo3_task_guide` on a bugfix states the obligation and
names no directory; and `typo3-core-patch-development` says only that the
directory "follows the branches the patch reaches rather than the branch it is
written on, so a backport does not go where the release under development goes",
which tells a session which directory is wrong and never which is right. Say the
rule affirmatively where the file is written — the `<lts>.x` directory of the
oldest branch the `Releases:` trailer names, duplicated into both where two
maintained lines take the change — in the skill at that step and in the task
guide's bugfix arm beside the obligation it already states, and make the
document's own section reachable from the words somebody writing one uses. The
statement itself is right and verified, so nothing about the rule is in
question: what is open is that it arrives after the file has been written.
