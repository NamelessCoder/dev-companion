# The presence check looks for the qualified tool name too

`skills/base.md` opens by making the first call the check for whether this
server is there at all: "No `typo3_` tool in this session, or a first call that
errors: stop, say this workflow needs the server and it is not there." A client
that defers tool schemas exposes them under a name carrying the server's own —
`mcp__<server>__typo3_project_describe` — so a search for the bare name comes
back empty on a session where the server is connected, and this line turns that
into an absence and prescribes abandoning the workflow. Say in the check that
the qualified form is what is looked for next, before the absence is concluded,
and assert the wording in `SkillTest::theBaseFixesTheOrderEveryTaskStartsIn`
where the base's load-bearing sentences are held. The initialize instructions
are fifteen characters from the cap a client keeps, so nothing goes there
(`D-SKL-084`), and the bare names in `nextTools` and the skills stay as they
are.
