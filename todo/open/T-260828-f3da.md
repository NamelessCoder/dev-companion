# What ddev composer does to a wrapped tool's stdout

`commands[].invocation` now carries the runnable form, and the half of that
feedback nothing here can answer is its second: the session reports that
`ddev composer cgl:ci` returned the failing exit code while php-cs-fixer's diff
never reached stdout, and that
`ddev exec ".build/bin/php-cs-fixer fix --diff --dry-run …"` printed it. Stand a
DDEV project up — `bin/cli environment:create` makes one — declare a composer
script wrapping a tool that writes its result to stdout, and read what each of
the two forms passes through. Where it holds, it is a statement in
`knowledge/hints/`, beside what a declared command is run as, rather than a
field: which of a repository's scripts wrap such a tool is not readable from the
manifest.
