# Each declared command carries the form the caller runs

`typo3_project_describe` says in prose that a declared command runs inside the
environment and not in the caller's shell, and its payload carries the command
as the manifest declares it. Add the field that carries the runnable form —
`ddev composer <name>` for a composer script and `ddev exec` for the rest, and
the command unchanged where `environment.entered` is true or there is no
environment — beside `command`, `source`, `declares` and `runs` in
`ProjectDescribe`'s schema, and assert it from a DDEV fixture on both sides of
`entered`, as `ProjectTest` already does for the prose. `D-ANS-126` has the
shape and the one case that would break it. The report's second half is not this
step: whether `ddev composer <script>` passes through the stdout of a tool the
script wraps needs a DDEV project to establish, and it is a hint rather than a
field.
