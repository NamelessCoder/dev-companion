# Carry the version-currency check into the answers and the skills

Two entries were written on 2026-08-29 and neither is built. `R-ANS-037` says an
answer names where the current release of node, a GitHub Action, DDEV or a
library is read rather than naming a version to adopt; `R-SKL-029` says a skill
reading a project checks what that project pins against the day's release and
reports what is behind.

Start with the sweep, because it says how much of the first one there is: read
`knowledge/` for a version number belonging to something outside TYPO3 — the
`hints/assets.json`, `hints/project.json` and `hints/testing.json` files are
where a build, a repository layout and a suite are described, and the documents
below `knowledge/documents/project/` and `knowledge/documents/extension/` are
the other half. A number the core declares as a floor stays and is not a
finding; what has to be rewritten is a version offered as the one to use. Where
the sweep finds nothing, that is the result: record what was read and mark
`R-ANS-037` judged rather than leaving it open on an unmeasured claim.

Then the skills, one checklist line each in the four whose task touches a pin:
`typo3-extension-asset-build` for `package.json` and the node the build runs on,
`typo3-development-installation` for `.ddev/config.yaml`,
`typo3-extension-health` and `typo3-extension-conformance` for
`.github/workflows/` and the declared dependencies. The line says the current
release is established on the day, that a pin behind it is a finding with the
raise offered, and that what the installed TYPO3 requires is what can speak
against raising. It names no version, which is the whole point —
`documentation/contributing/writing-a-skill.rst` is what a new line is written
under, and `SkillTest` is where a line that has to hold gets a test.

Whether the check earns a tool is a separate question and is not this step: it
would have to reach a release schedule per ecosystem, and `D-FBK-027` is the
measure such a lookup has to pass.
