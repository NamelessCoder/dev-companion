# Answer a change with the review it is in

**Serves:** feedback/2026-08-13-214644-typo3-gerrit-lookup-returns-no-review-comments.md
**Priority:** normal
**Branch:** todo/answer-a-change-with-the-review-it-is-in

Judged as `D-ANS-079`: step 1b, the shape is missing. The review skill routes
its unanswered-comment surface to `typo3_gerrit_lookup`, the answer carries
nothing about the review, and the session fetched the NoteDB meta ref and read
it as git history instead. The entry carries the boundary and what it measured
against `review.typo3.org`; the schema is what it left open.

A change answer gains the votes and the comments. The votes come from
`o=DETAILED_LABELS` with `o=DETAILED_ACCOUNTS` on the call `Gerrit::search()`
already makes: per label, the value each voter holds and whether the label is
satisfied. The comments come from `/changes/<number>/comments`, one further
call, each carrying its author, patch set, file, line, `unresolved` and
`in_reply_to`. The message log is behind a parameter because it is 50 KB against
14 KB, and the bot half is separated the way `notes` does it on
`typo3_forge_lookup` — Gerrit tags what it generates as
`autogenerated:gerrit:*`. None of it reaches the issue search, and the answer
gains `changeId` while `Gerrit::change_()` is open.

The open choice, and the reason this is not a spot fix: what the vote, comment
and message records are called and which fields they hold, and whether the vote
half names the copy condition that dropped a vote — which is in the messages
rather than in the labels, so stating it there means fetching them anyway.
Decide it against `src/Result/Schema.php` and say which in the commit.
`GerritTest` is where the cases go, one per change that has votes, comments,
neither, and a comment somebody replied to without resolving.
