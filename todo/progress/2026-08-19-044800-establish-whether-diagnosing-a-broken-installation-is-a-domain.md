# Establish whether diagnosing a broken installation is a domain

**Serves:** skills/, D-SKL-005
**Priority:** normal
**Branch:** todo/establish-whether-diagnosing-a-broken-installation-is-a-domain
**Claimed:** 2026-08-19

Three of the seventeen tasks in the same benchmark were one shape — a page
answers with an error or renders the wrong thing, and the request is the file
and the cause with nothing changed yet — and no published skill's description
covers it, because the twelve name building, reviewing, upgrading, testing and
installing. Carry that shape through the research
`documentation/contributing/writing-a-skill.rst` asks for before the first line
is written: what a session actually does to find such a cause, which of those
steps are lookups this server already owns, and whether what is left over is a
workflow or a single call. `D-SKL-035` charges a new domain a run without the
skill, so the prompt belongs in `scenarios/contracts/` before a `SKILL.md`
exists. A negative result closes this: a shape nobody can write an order for is
an answer, and recording it is what stops the next reading of the same gap
starting over.
