# Weigh whether the project answer hands on to the task guide

**Serves:** D-AUD-012
**Priority:** normal
**Branch:** todo/weigh-whether-the-project-answer-hands-on-to-the-task-guide
**Claimed:** 2026-08-21

The benchmark of 2026-08-19 called `typo3_project_describe` eleven times across
seventeen project tasks and `typo3_task_guide` once. Read on the same day,
`ProjectDescribe` names `typo3_rule_lookup` for the guides it lists and does not
name `typo3_task_guide` at all — so the call that fires ends without handing on
to the call that does not, on the shortest channel this server has after the
instructions.

What is open is whether it should, and what it costs. `D-ANS-087` holds that the
project answer stays whole because a call is what costs, so a sentence is
cheaper than a field, and the answer already carries one onward pointer to weigh
it against. `D-SKL-013` is the other side of the reading: on this same
benchmark, a skill name delivered in a tool's own answer in the turn that asked
for it did not fire either, so an onward name in an answer is a channel with one
recorded failure already.

Settle it against those two rather than against the eleven to one alone, and
record the reading whichever way it goes.
