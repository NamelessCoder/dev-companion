# The repository's own AGENTS.md routes agents around a tool that answers better

Push the patch below from a contribution checkout, having filed the Forge issue
it names. It is the Context list's issue-tracker bullet of `typo3/AGENTS.md`,
which today gives a `curl` recipe and names no MCP server anywhere in the file,
so an agent following it never calls the tool that answers the same question
better. The bullet is byte-identical on `main`, `14.3` and `13.4`, read on
2026-08-27, and a task goes to `main` and `14.3`.

```markdown
- Issue tracker: <https://forge.typo3.org> (Redmine). Where the
  `typo3/dev-companion` MCP server is connected, `typo3_forge_lookup` answers it:
  one issue with its comments, a word search, or the open backlog filtered and
  ordered. Without it, query the JSON API with
  `curl -H "Accept: application/json"` and the **default curl user agent** —
```

Those five lines replace the bullet's first two, and everything from
`browser-like user agents` down stays as it is — so a session without the server
reads what it reads today.

`typo3_commit_message_guide` with `workflow="core"` drafted the message and
checked it: subject
`[TASK] Name typo3_forge_lookup in the issue tracker bullet`, a `Resolves:` line
for the issue, `Releases: main, 14.3`, and the `Signed-off-by` that
`git commit -s` writes from the committer's own identity — which is the
Developer Certificate of Origin and is the maintainer's to state, whatever wrote
the line.

Nothing on this server failed here: the reporting session held both the recipe
and the tool, took the tool, and said what the tool gave it that `curl` could
not. What is corrected is a routing table this repository does not own, which is
why
[`D-AUD-013`](../../decisions/audience/aud-013-a-competing-route-is-corrected-where-it-is-written.md)'s
third **Wrong if** is what the outcome is read against.
